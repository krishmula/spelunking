## Candidate for screening

At the *first mismatch* in a grammar-masked draft, how often did the target choose a token that the pruned draft head cannot represent? Among prefixes where the grammar allows a genuine choice, does that account for enough lost time to matter after forced-token drafting and an inexpensive prompt n-gram baseline? This is a question about an attribution error in the usual counters. A grammar mask that contains at least one draft token can still omit the target's top choice from the draft vocabulary (S4, S7). The application should be ordinary tool calls on public schemas, including short identifiers and enum values. A stress test with invented rare keys is a separate sensitivity check.

Existing answers are substantial. NVIDIA applies draft grammar masks and accounts for CPU and GPU costs (S8). The vLLM issue reports zero empty intersections across 4,486 masks, plus separate tests on an enum-heavy schema. These are developer-reported measurements on an older engine (S7). FactorSpec already accelerates forced portions, compares EAGLE and n-grams on BFCL and retail tasks, and tests different proportions of free text (S6). SpecVocab provides a dynamic shortlist, and its repo documents tied full-vocabulary and fixed reduced-vocabulary controls (S4, S9). No source here attributes first rejections specifically to missing target choices after equivalent forced-token processing. The public-gap confidence is low.

**Cheapest test.** Start with greedy, teacher-forced replay of target-generated legal outputs. At each reached non-forced position record whether the target argmax belongs to the legal draft vocabulary. For each verification block record whether the *first* rejection was such a miss. Exclude positions after an earlier rejection from the observed opportunity. Use the same tokenizer and grammar backend for every baseline. Recompute block boundaries on the reference transcript under an oracle that repairs only missing target choices, giving it zero extra cost. Count saved target passes. Use a second optimistic bound granting the rest of each repaired block perfect predictions if the conditional drafter cannot be replayed. Compare the optimal no-cost repair with measured baseline time per block by verify width and batch. The metric is time saved per completed valid call. A raw fraction of missed token IDs cannot establish it.

Use held-out schema families from real tool benchmarks, segregating fixed syntax, constraint-forced values, finite choices, and free text. Match any semantic relations in FactorSpec across all baselines or restrict the comparison to the common syntax-only language. Run no-speculation, grammar-masked EAGLE, grammar jump-forward with n-grams, fixed full-vocabulary draft and SpecVocab on a common target and precision. Use masked-target agreement for greedy and distributional equivalence if later evaluating sampling. Record correctness, completed valid calls/s, TPOT, TTFT, and p95 completion time at batch 1, batch 8 and an arrival-rate sweep. Corpus replay needs a tokenizer, draft vocabulary map and target transcript. GPU profiling requires the actual serving stack and compatible checkpoints, whose availability is unconfirmed.

**Proposed decision rule.** Stop if the upper bound cannot save 5% of elapsed decode time on two held-out schema families, or if a full-vocabulary or n-gram baseline captures the gain at equal cost. A larger bound only warrants timing a feasible alternative. The threshold is a project heuristic. No experiment ran. A multilingual extension remains a separate author-named direction, not evidence that an optimizer would help.

Searches covered grammar and pruned-vocabulary EAGLE, enum choices and fallback, dynamic speculative vocabularies, relational/forced drafting, deterministic prefix sharing, and ReDrafter deployment. Private serving workloads and unreleased systems are outside the evidence.
